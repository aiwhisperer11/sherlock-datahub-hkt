# Architecture

Sherlock is split into two independent repositories. `sherlock-datahub-backend` owns the REST API and investigation model; `sherlock-datahub-web` owns the browser dashboard. They communicate only through the REST contract.

```text
Next.js dashboard ── REST ──> FastAPI API ──> MetadataProvider
                                      ├── SandboxMetadataProvider (implemented)
                                      └── DataHubMetadataProvider (planned)
```

## Backend flow

`GET /api/v1/demo/stale-pipeline` loads the labelled JSON fixture, validates it into Pydantic models, and returns it as an `Investigation`. The fixture includes observations, evidence, confidence components, graph relationships, conclusion, and recommended action.

## Provider boundary

`MetadataProvider` keeps metadata acquisition separate from evidence interpretation. The sandbox provider is deterministic and supports demo/test workflows. The DataHub provider deliberately raises `NotImplementedError` until the MCP capability gate is completed; no credentials, endpoints, or fabricated calls are present.

## Operational properties

- CORS origins are set with `SHERLOCK_CORS_ORIGINS`; the local default is `http://localhost:3000`.
- OpenAPI is generated by FastAPI at `/docs`.
- JSON is the current persistence mechanism; SQLite can be added later for durable investigations without changing the REST model.
